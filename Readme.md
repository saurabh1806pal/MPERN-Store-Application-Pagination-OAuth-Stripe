# 🛍️ MPERN Store — Full-Stack Learning Project

> A step-by-step, production-minded learning project built with **MongoDB, PostgreSQL, Express.js, React.js, and Node.js**.

**Goal:** Build a product store that supports authentication, email verification, Google sign-in, searchable and sortable product listings, pagination, and Stripe checkout.

## 🧰 Technology Stack

| Layer | Technology | Purpose |
|---|---|---|
| Frontend | React + Vite | User interface and development server |
| Backend | Node.js + Express | REST API and business logic |
| Document database | MongoDB + Mongoose | Product catalog and flexible product metadata |
| Relational database | PostgreSQL + `pg` | Users, orders, and payment records |
| Authentication | JWT + password hashing | Session/authentication flow |
| Google sign-in | Google OAuth / OpenID Connect | Identity-provider login |
| Payments | Stripe Checkout + webhooks | Checkout and verified payment updates |
| Configuration | `dotenv` | Environment variables |
| API development | Postman or equivalent | Manual endpoint testing |

> **Data ownership:** This project uses MongoDB for product catalog data and PostgreSQL for relational account/order/payment data. Keep a clear source of truth for each entity; avoid duplicating records without a defined synchronization strategy.

## 🚀 Installation: Initial Setup

Run these commands from the directory where you want to keep the project.

### 1. Create the React frontend

```bash
mkdir mpern-store
cd mpern-store

npm create vite@latest client -- --template react
cd client
npm install
cd ..
```

### 2. Create the Express backend

```bash
mkdir server
cd server
npm init -y

npm install express mongoose pg dotenv cors cookie-parser
npm install -D nodemon
```

Add a development script to `server/package.json`:

```json
{
  "scripts": {
    "dev": "nodemon server.js",
    "start": "node server.js"
  }
}
```

> If `package.json` already contains other fields, keep them and update only the `scripts` section. This initial setup uses JavaScript and ES modules only if configured consistently; the first implementation will establish the module format.

### 3. Configure environment files

Create `server/.env.example`:

```dotenv
PORT=5000
CLIENT_URL=http://localhost:5173

MONGODB_URI=
DATABASE_URL=

JWT_SECRET=

GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=

EMAIL_HOST=
EMAIL_PORT=
EMAIL_USER=
EMAIL_PASSWORD=

STRIPE_SECRET_KEY=
STRIPE_WEBHOOK_SECRET=
```

Create a local `server/.env` using your own values. Never commit real secrets.

For the frontend, create `client/.env.example` only for non-secret public configuration, for example:

```dotenv
VITE_API_URL=http://localhost:5000/api
```

**Never place private keys, database credentials, JWT secrets, or Stripe secret keys in frontend variables.** Vite exposes `VITE_*` variables to browser code.

### 4. Database setup

**MongoDB Atlas**
1. Create an Atlas project and database deployment.
2. Create a database user with a strong password.
3. Configure network access for your development environment.
4. Copy the application connection URI into `MONGODB_URI`.
5. URL-encode special characters in credentials if required.

Official guide: [MongoDB Atlas](https://www.mongodb.com/cloud/atlas/register)

**PostgreSQL**
1. Install PostgreSQL locally or use a managed provider.
2. Start the database server.
3. Create a database named `mpern_store`.
4. Put the connection string into `DATABASE_URL`.
5. Add schema creation and migrations during Phase 2.

For macOS, see [Postgres.app](https://postgresapp.com/) or the [official PostgreSQL macOS options](https://www.postgresql.org/download/macosx/).

### Product listing query example

```http
GET /api/products?search=phone&page=1&limit=10&sortBy=price&order=asc
```

A successful response could follow this shape:

```json
{
  "items": [],
  "pagination": {
    "page": 1,
    "limit": 10,
    "totalItems": 0,
    "totalPages": 0
  }
}
```

The backend must validate `page`, cap `limit`, allowlist sortable fields, and use parameterized queries or safe Mongoose filters. Never pass arbitrary user input directly into database operators or SQL strings.

## 🔐 Security Checklist

- [ ] Hash passwords with a suitable password-hashing algorithm.
- [ ] Use short-lived, securely managed verification tokens.
- [ ] Set authentication cookies with appropriate `HttpOnly`, `Secure`, and `SameSite` attributes when using cookie-based sessions.
- [ ] Configure CORS for the intended frontend origin and credentials policy.
- [ ] Verify Google identity tokens server-side and validate audience/issuer.
- [ ] Keep all secrets on the backend.
- [ ] Validate and authorize every protected request.
- [ ] Verify Stripe webhook signatures using the raw request body as required by Stripe.
- [ ] Treat webhook events as retryable and make payment processing idempotent.
- [ ] Do not mark an order paid based only on the browser's success redirect.
- [ ] Never store raw card details.
- [ ] Use HTTPS in production and avoid logging passwords, tokens, or payment secrets.
